# Local declarative plugin API 1

Manage plugins in tray → **Local components / plugins…**. Install local ZIP, inspect
the displayed permissions, explicitly enable, then drag a matching file → Shift →
Ctrl → the contextual action (Tab if on a later page). Disable and uninstall there.
No marketplace or automatic update fetch exists.

Packages contain `manifest.json` and optionally `README.md`, no subdirectories,
executables, DLLs, scripts or installation hooks. Compressed/expanded limits are
2 MB per package, two entries, 1 MB per entry. Schema/API must equal 1, version must
parse with major ≥1, and identifiers are lowercase ASCII letters/digits/dot/hyphen.
Unknown JSON fields, capabilities, operations and unsafe ZIP paths are rejected.

```json
{
  "SchemaVersion": 1,
  "Id": "sample.hash",
  "Name": "SHA-256",
  "Version": "1.0.0",
  "ApiVersion": 1,
  "Capabilities": ["read-selection", "write-result"],
  "Actions": [
    {"Id":"hash", "Label":"SHA-256", "Operation":"sha256", "Extensions":["PNG","JPG","PDF","TXT"]}
  ]
}
```

The currently supported operations are `sha256` (selected file ≤256 MB) and
`text-statistics` (strict UTF-8 ≤8 MB; TXT/HTML/SRT/VTT). Text statistics counts Unicode
text elements, whitespace-delimited words, lines and UTF-8 bytes; it is not an HTML
renderer or language tokenizer. Outputs are independently recomputed by the parent
and published as collision-safe new JSON reports beside the original.

Up to four actions per package, 40 extensions per action, 16-character action
labels. Extensions only advertise file types recognized by this Naqla build.
The approval is tied to a SHA-256 fingerprint of package names/content. Changing
manifest/README disables registration until the user enables the changed package.

Two working examples are generated by `scripts/build-sample-plugins.py` into
`artifacts/sample-plugins`. They are installed **disabled**, with the same controls
as any other local package.

## Isolation and security limits

The host is the trusted Naqla executable's fixed worker entry, in a separate hidden
normal-user process. It receives only an owned staged input and an allowlisted
operation, not arbitrary commands. The parent limits response size, duration and
checks results. Windows Job Objects clean descendants, cap process count/memory;
cancellation/failure does not terminate the tray process.

This is process separation, **not an OS filesystem/network sandbox**. Arbitrary
third-party executable plugins are unsupported, rather than falsely described as
sandboxed. SHA-256 identifies package bytes, not publisher authenticity. Native
crash-injection/long-session hostile-input coverage remains a manual release gate;
automated tests cover worker failures, restart, timeout/lifetime cleanup,
cancellation and malicious package rejection.

For broader extensibility, the compatible next step is to expand trusted
allowlisted operations/recipes. Executing arbitrary third-party assemblies would
need a separately reviewed restricted host (for example AppContainer filesystem/
network capabilities), a new threat model and native acceptance tests. It is not
silently enabled by this initial declarative API.
