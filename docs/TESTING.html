Install and first activation

  1. Run artifacts/Naqla-Dev-Setup-win-x64.exe. Keep “Launch Naqla” checked. Startup is a visible per-user option, also available in the tray menu.
  2. Expect a tray icon and no main window. Right-click it → Diagnostics → Show diagnostic status. Confirm logging is available, then Mark test start.
  3. In Explorer, grab a supported local file with the left mouse button. Keep the button down, move beyond the normal drag threshold, and press Shift.
  4. Expect the existing small transparent Pixel-Modern wheel near the pointer. Actual OLE delivery fills its hub with extension/size; a hook alone cannot do so. Move slightly across the wheel if Explorer has not delivered DragEnter yet.
  5. Release Shift while still dragging. Tap Ctrl for Tools. Releasing Ctrl keeps Tools selected; another Ctrl press returns to Convert.
  6. When Tools has several pages, center dots indicate the page. Tab advances; Shift+Tab goes back. At most six tool sectors appear. These keys are intercepted only during the confirmed drag, with Tools open and multiple pages available.
  7. Hover an available sector and release the left button. The wheel closes. A contextual editor opens when the operation needs settings or confirmation; otherwise processing starts. Conversion outputs use new collision-safe names beside each source. Smart Rename changes actual names only after confirmation.
  8. Escape, releasing outside the wheel or cancelling an editor must publish no output for that cancelled task. A valid Explorer drop elsewhere follows Windows behavior; Naqla cannot undo an unrelated destination's normal operation.

Offline test

On a disposable test account/VM, install the development app and import desired packs while local. Disconnect that test environment's networking yourself, then repeat F01, F05, F08–F23. Expect no login, download or cloud request. Record actual observations. Source-code inspection is not a substitute for this test. Naqla's worker Job Objects limit resources/lifetime; they are not a network sandbox.

If Shift shows nothing — return these items

  • Row ID, build, Windows version, scale/monitor, source extension/category and approximate size, Desktop versus Explorer, exact key order and whether Ctrl was held before activation. No personal path is needed.
  • The marked session's session-*.jsonl from %LOCALAPPDATA%\Naqla\Diagnostics plus the diagnostic status text. The closed log schema excludes paths, filenames, text contents and raw exception messages. Do not send rename recovery records.
  • A cropped screenshot/short recording from grabbing the test fixture through Shift, plus any error/result panel. Hide unrelated Explorer paths, personal names and files. For a conversion failure, provide the result-panel details and output's actual size/extension; share a non-sensitive fixture only if comfortable.
